## 1. 原型目的

需求规格说明书将系统定位为“科研项目材料与节点台账”，并在 FR-03 中要求流程模板可配置。传统后台表单难以直观调整“节点周期比例、材料归属、截止锚点”等结构性配置，因此本次原型重点解决四件事：

1. 用 **ERP 截图 OCR** 把项目基本信息自动带入新建项目表单，并允许通过开关锁定识别结果。
2. 用**可拖拽的周期时间轴**表达“节点占项目周期的哪一段”，拖动即改比例，实时看到节点计划日期与材料截止日期。
3. 用**材料编排看板**表达“材料归属哪个节点”，跨列拖动即可调整归属，避免逐条打开表单修改。
4. 用**拖拽文件到材料行**完成归集与逾期补传，贴近项目经理日常操作习惯。

同时，原型覆盖按 ERP 字段调整的新建项目表单、字段内容维护、菜单启停、季度报表、经费台账、逾期提醒、分类台账、系统管理与展示大屏，保证演示时能从登录一路走到大屏。

## 2. 运行与演示账号

```text
双击 prototype/start.cmd（或 start.ps1）
命令行：cd prototype && node server/index.mjs
停止服务：双击 prototype/stop.cmd
```

启动器会先探测 `http://127.0.0.1:8088/api/health`：若服务已在运行则只打开浏览器，不会重复启动；端口被其他程序占用时给出明确提示；端口空闲时才拉起 Node 服务，就绪后再打开浏览器。`start.cmd` 使用 ASCII + CRLF 保存，避免中文批处理在 cmd 的 GBK 代码页下被拆坏；`stop.cmd` 只会结束本原型的 `server/index.mjs` 进程。

## 4. 拖拽交互设计

### 4.1 周期时间轴

- **整体平移**：按住节点块拖动，开始与结束比例同步平移，步进 1%，范围约束在 0%—100%。
- **调整起止**：拖动节点块左右边缘把手，分别调整开始或结束比例；允许零宽度节点（如“成果归档 100%—100%”），此时通过右侧“开始/结束偏移天数”表达项目结束后 30 天。
- **实时反馈**：拖动过程中节点块位置、左侧节点日期、顶部“今天”标记即时变化；松手后重绘并标记“有未保存的修改”。
- **零宽节点**：渲染为末端胶囊标签，仍可拖动、选中和在检查器中修改。
- 保存后调用 `PUT /api/templates` 全量落库；页面顶部显示最近保存时间。

### 4.2 材料编排看板

- 每个节点一列，列出材料卡片及其“必备/选交、业务分类、截止锚点、偏移、编码”。
- 拖材料卡片到其他节点列：材料归属改变，序号自动重排。
- 拖到某张卡片上方：插入到该位置，实现同类材料排序。
- 拖动列头到另一列：节点顺序重排，影响新项目生成顺序。
- 点击节点或材料：右侧属性检查器即时可编辑，不离开当前画布。

### 4.3 项目材料归集

- 将文件拖到材料表格任意一行，行高亮后松手即上传；上传完成自动刷新材料状态、附件数、节点完成度与提醒。
- 材料详情抽屉内提供拖拽/点击上传区、补传说明、附件列表（预览、下载、删除）。
- 上传日期晚于截止日期时标记“逾期提交”；删除最后一个附件回退“待提交”。

### 4.4 项目字段配置

针对“新建科研项目”的信息可配置诉求，系统管理新增「项目字段」页签：

- 新建项目表单已按 ERP「基本信息」页重构为 **ERP 基本信息**（23 项，含项目简称、项目代号、合同运行额、成本控制额、税款类别、代号类型、计划利润、预立项、重大立项、结算状态、立项时间/序号、项目总工、安全员、是否转化项目、工期、立项经费说明、备注）与 **系统信息**（项目编号、级别、来源、经费来源、状态、进度、批复经费、ERP 采购/询比编号）两组。
- 支持新增、删除、修改字段，以及拖拽行调整表单顺序；字段类型包括单行文本、多行文本、数字、日期、下拉选择、是/否勾选。
- 可配置必填、整行显示、占位提示、字段说明、所属分组与 **OCR 识别关键词**；下拉字段可打开「选项」面板，对字段内容（选项）增删改和上下移动。
- 项目名称、部门、项目经理、起止日期、经费、状态等锁定字段不可停用，避免破坏日期重算、权限范围与统计口径。
- 保存后新建/编辑项目表单即时生效；自定义字段值随项目保存，并在项目详情「项目信息 → 自定义信息」中展示。
- 界面右上角关闭按钮（弹窗、抽屉）与遮罩、Esc、取消按钮均可关闭。

### 4.5 ERP 截图 OCR 识别

新建项目弹窗顶部提供 OCR 区：

- 支持点击或拖拽上传 PNG/JPG/WebP/BMP 截图，自动调用 `/api/ocr` 识别；截图不写库，识别后立即删除临时文件。
- 服务端优先调用本地 RapidOCR（Python），识别文字块坐标后按字段配置的 OCR 关键词定位标签与右侧值，并按字段类型归一化：日期转 `YYYY-MM-DD`、金额去千分位、部门/人员匹配 ID、下拉匹配选项、勾选项转布尔。
- 识别结果回填表单，并以淡紫色边框标识；成本控制额（元）自动换算批复经费（万元）。
- 「允许修改识别结果」开关默认开启；关闭后，本次识别到的字段全部只读锁定，重新开启即可修改。未被识别的字段始终可手工填写。
- 显示识别引擎、耗时、匹配字段数、待确认项与 OCR 原始文本；识别失败可继续手工建档。
- RapidOCR 不可用时自动回退 Windows 内置中文 OCR，并在状态栏提示。

### 4.6 菜单启停

系统管理新增「菜单管理」页签：

- 对左侧 14 个菜单逐项启用/停用；停用后导航隐藏，直接输入地址也会显示“该菜单已停用”。
- 运行总览、项目台账、系统管理为锁定菜单，防止管理员把自己锁在系统外。
- 保存后写入配置并刷新页面，菜单与直接访问校验同时生效。

## 5. 计算规则落地

原型与需求文档第 6 章保持一致，并在前端预览与服务端落库两处使用同一套公式：

```text
节点计划开始 = 项目开始 + round(项目周期天数 × startRatio) + startOffsetDays
节点计划结束 = 项目开始 + round(项目周期天数 × endRatio)   + endOffsetDays
材料截止日期 = 锚点日期（节点开始/结束、项目开始/结束） + offsetDays
季度报表截止 = 季度末 + 15 天
```

节点状态：必备材料全部完成（已提交/逾期提交/无需提交）即“已完成”，否则按计划开始日期区分“未开始/进行中”。材料与报表的逾期由查询实时计算，不使用定时任务。

## 6. 技术形态

为避免评审环境缺少 JDK/MySQL 或无法访问 npm，原型采用“零依赖 Node 服务 + 原生 ES Module 前端”；OCR 使用本地 Python 适配器：

- 后端：`node:http`，JSON 文件持久化（临时文件 + 原子改名），PBKDF2 密码、HMAC-SHA256 Token，统一 `{code,message,data}` 响应。
- OCR：`/api/ocr` 优先调用本地 RapidOCR（`tools/ocr.py`），失败回退 Windows 内置 OCR（`tools/ocr.ps1`）；`server/ocr.mjs` 负责按字段 OCR 关键词解析坐标文本并归一化。
- 前端：原生 ES Module + 手写组件与 SVG 图表，无构建步骤；设计系统为深蓝侧栏 + 浅色工作台，大屏为暗色主题。
- 接口：`/api/auth`、`/api/projects`、`/api/templates`、`/api/materials`、`/api/attachments`、`/api/quarterly`、`/api/alerts`、`/api/dashboard`、`/api/categories`、`/api/project-fields`、`/api/ocr`、`/api/menus`、`/api/users`、`/api/departments`、`/api/logs`、`/api/display`。
- 迁移到正式系统时，只需替换 `public/js/core/api.js` 的请求实现并逐页迁移到 Vue 3，交互与接口契约保持不变；OCR 可替换为云端高精度服务，无需改前端字段映射。

## 8. 边界与后续

- 原型为单机运行，`data/db.json` 未做多进程并发写锁；多人同时操作应以正式后端事务为准。
- 附件通过 JSON Base64 上传，单文件限制 20MB；正式系统按需求文档改为流式上传、SHA-256 校验与对象存储。
- OCR 使用本地引擎，准确率依赖截图分辨率与版式；本原型针对 ERP「基本信息」页的标签布局做关键词定位，换版式时在字段配置中调整 OCR 关键词即可。生产环境建议替换为云端高精度 OCR，并在识别后保留人工确认环节。
- 展示访问码为演示值 `research2026`，生产环境通过 `DISPLAY_KEY` 覆盖。
- 不含审批流、电子签章、消息推送、统一身份认证等需求明确排除的内容。
- 模板设计器的“比例 + 偏移 + 快照”模型已按正式系统数据结构设计，可直接迁移到 Spring Boot 服务层。
