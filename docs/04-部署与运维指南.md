# 部署与运维指南

本文档覆盖本机开发部署、通用 Windows/Linux 部署、Docker 部署、配置项、备份升级和常见问题。习惯使用 IntelliJ IDEA 的开发者可同时参考《08-IntelliJ启动指南.md》。

| JDK | 17 | 17 LTS | 17.0.2 |

## 3. 本机快速部署（Windows）

> 一键启动 MySQL、后端、前端：双击或在项目根目录执行 `scripts\start-all.cmd`。需要分步排查时按本节顺序执行。

### 3.1 目录约定

```text
F:\Deepseekworkplace\
├─ tools\                      预置 JDK、Maven、MySQL、Node
└─ research-material-system\   本项目
```

如果目录不同，脚本会自动按项目上级目录查找 `tools`，也可以手动传参。

### 3.2 启动 MySQL

本机 MySQL 使用 `tools\mysql-my.ini`，数据目录 `tools\mysqldata`，端口 3307。

```powershell
cd F:\Deepseekworkplace\research-material-system
.\scripts\start-mysql.cmd
```

脚本会检查 3307 是否已监听；已运行则直接退出。

手动启动：

```powershell
& F:\Deepseekworkplace\tools\mysql-8.0.29-winx64\bin\mysqld.exe `
  --defaults-file=F:\Deepseekworkplace\tools\mysql-my.ini
```

### 3.3 初始化数据库

> 该脚本会 **删除并重建** `research_material` 库中的业务表。仅用于首次部署或演示重置。

```powershell
.\scripts\init-db.cmd
# 输入 YES 确认
```

等价手动命令：

```powershell
$mysql = "F:\Deepseekworkplace\tools\mysql-8.0.29-winx64\bin\mysql.exe"
cmd /c "`"$mysql`" --host=127.0.0.1 --port=3307 --user=root --default-character-set=utf8mb4 < `"db\schema.sql`""
cmd /c "`"$mysql`" --host=127.0.0.1 --port=3307 --user=root --default-character-set=utf8mb4 < `"db\data.sql`""
```

如果 root 有密码：

```powershell
$env:MYSQL_PWD = "your-password"
# 再执行 mysql 命令
Remove-Item Env:MYSQL_PWD
```

### 3.4 启动后端

```powershell
.\scripts\start-backend.cmd
```

脚本会：

1. 自动查找 JDK 17 和 Maven。
2. 使用 `tools\maven-settings.xml`（存在时）构建。
3. 设置 `DB_PORT=3307`。
4. 设置 `STORAGE_ROOT=backend\data\uploads`，将附件固定到项目目录，便于备份。
5. 使用 `local` profile 启动，生成演示数据（仅空库时）。
6. 将 Tomcat 临时目录放到 `backend\data\tomcat`，避免 Windows 临时目录权限问题。

手动启动：

```powershell
$env:JAVA_HOME = "F:\Deepseekworkplace\tools\jdk-17.0.2"
$env:DB_PORT = "3307"
& "$env:JAVA_HOME\bin\java.exe" -Djava.io.tmpdir="$PWD\backend\tmp" `
  -jar "backend\target\research-material-backend.jar" `
  --spring.profiles.active=local `
  --server.tomcat.basedir="$PWD\backend\data\tomcat"
```

健康检查：

```powershell
curl.exe http://127.0.0.1:8080/api/health
```

预期：

```json
{"code":0,"message":"ok","data":{"status":"UP","service":"research-material-backend","time":"..."}}
```

### 3.5 启动前端

新开一个 PowerShell 窗口：

```powershell
.\scripts\start-frontend.cmd
```

访问 <http://localhost:5173>。

如果 pnpm 未安装：

```powershell
npm install -g pnpm@11
cd frontend
pnpm install
pnpm dev
```

## 4. 通用 Windows / Linux 部署

### 4.1 安装基础软件

Windows：

- 安装 JDK 17（配置 `JAVA_HOME`）。
- 安装 Maven 3.9（配置 `PATH`）。
- 安装 MySQL 8.0，创建数据库用户。
- 安装 Node 20+ 仅用于构建前端；生产不需要 Node。

Linux（Ubuntu 示例）：

```bash
sudo apt update
sudo apt install -y openjdk-17-jdk maven mysql-server nginx
# Node 20：使用 NodeSource 或 nvm
```

### 4.2 创建数据库

```bash
mysql -uroot -p < db/schema.sql
mysql -uroot -p < db/data.sql
```

如果数据库用户不是 root，先创建：

```sql
CREATE USER 'research'@'%' IDENTIFIED BY 'StrongPassword!2026';
GRANT ALL PRIVILEGES ON research_material.* TO 'research'@'%';
FLUSH PRIVILEGES;
```

### 4.3 构建后端

```bash
cd backend
mvn -DskipTests package
```

产物：`backend/target/research-material-backend.jar`。

启动：

```bash
export DB_HOST=127.0.0.1
export DB_PORT=3306
export DB_NAME=research_material
export DB_USERNAME=research
export DB_PASSWORD='StrongPassword!2026'
export AUTH_SECRET='replace-with-a-long-random-secret'
export DISPLAY_ACCESS_KEY='your-display-key'
export DEMO_ENABLED=false
export STORAGE_ROOT=/opt/research-material/data/uploads

java -Djava.io.tmpdir=/opt/research-material/data/tomcat \
     -jar target/research-material-backend.jar \
     --spring.profiles.active=prod \
     --server.port=8080 \
     --server.tomcat.basedir=/opt/research-material/data/tomcat
```

> `prod` profile 在代码中未单独定义，等价于默认 `application.yml` + 环境变量；使用 `--spring.profiles.active=prod` 时不会加载 `application-local.yml`，因此不会生成演示数据。

### 4.4 构建前端

```bash
cd frontend
pnpm install
pnpm build
```

产物：`frontend/dist/`。

### 4.5 配置 Nginx

将 `frontend/nginx.conf` 复制到 `/etc/nginx/conf.d/research-material.conf`，按实际路径和后端地址调整：

```nginx
server {
    listen 80;
    server_name research.example.com;
    root /opt/research-material/frontend/dist;
    index index.html;
    client_max_body_size 60m;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

检查并重载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### 4.6 systemd 服务（推荐）

`/etc/systemd/system/research-material.service`：

```ini
[Unit]
Description=Research Material Backend
After=network.target mysql.service

[Service]
Type=simple
User=research
WorkingDirectory=/opt/research-material/backend
Environment=DB_HOST=127.0.0.1
Environment=DB_PORT=3306
Environment=DB_NAME=research_material
Environment=DB_USERNAME=research
Environment=DB_PASSWORD=StrongPassword!2026
Environment=AUTH_SECRET=replace-with-a-long-random-secret
Environment=DISPLAY_ACCESS_KEY=your-display-key
Environment=DEMO_ENABLED=false
Environment=STORAGE_ROOT=/opt/research-material/data/uploads
ExecStart=/usr/bin/java -Djava.io.tmpdir=/opt/research-material/data/tomcat -jar /opt/research-material/backend/research-material-backend.jar --server.port=8080 --server.tomcat.basedir=/opt/research-material/data/tomcat
Restart=on-failure
RestartSec=5
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now research-material
sudo systemctl status research-material
```

## 5. Docker Compose 部署

适用：Linux 服务器，已安装 Docker 24+ 与 Compose v2。

```bash
cd deploy
cp .env.example .env
# 修改 .env：数据库密码、AUTH_SECRET、DISPLAY_ACCESS_KEY、端口
docker compose up -d --build
```

访问：

- 前端：<http://服务器IP:8088>
- 后端健康检查：<http://服务器IP:8080/api/health>
- MySQL：宿主机 3307（可改 `MYSQL_PORT`）

说明：

- 首次启动时 MySQL 会执行 `db/schema.sql` 与 `db/data.sql`。
- `DEMO_ENABLED=false`，不会生成演示项目。
- 三个持久化卷：`mysql-data`、`uploads`、`tomcat-temp`。
- 修改代码后：`docker compose up -d --build`。
- 查看日志：`docker compose logs -f backend`。
- 停止：`docker compose down`（保留卷）；彻底清理：`docker compose down -v`（会删除数据）。

> 生产环境建议把 MySQL 放在独立主机或云数据库，并使用 `DB_HOST` 指向外部地址，去掉 compose 中的 mysql 服务。

## 6. 配置项

### 6.1 后端环境变量

| 变量 | 默认 | 必改 | 说明 |
| --- | --- | --- | --- |
| `SERVER_PORT` | 8080 | 否 | 服务端口 |
| `DB_HOST` | 127.0.0.1 | 是 | 数据库地址 |
| `DB_PORT` | 3306 | 是 | 数据库端口 |
| `DB_NAME` | research_material | 否 | 数据库名 |
| `DB_USERNAME` | root | 是 | 数据库用户 |
| `DB_PASSWORD` | 空 | 是 | 数据库密码 |
| `AUTH_SECRET` | 开发默认值 | **是** | Token 签名密钥，建议 32 位以上随机字符串 |
| `AUTH_EXPIRE_HOURS` | 12 | 否 | Token 有效期 |
| `STORAGE_ROOT` | ./data/uploads | 是 | 附件目录，生产用独立数据盘 |
| `DISPLAY_ACCESS_KEY` | research-display-2026 | **是** | 大屏访问码 |
| `QUARTERLY_DUE_DAYS` | 15 | 否 | 季度报表截止天数 |
| `ALERT_UPCOMING_DAYS` | 30 | 否 | 即将到期天数 |
| `CORS_ALLOWED_ORIGINS` | localhost:5173 等 | 是 | 生产填前端域名 |
| `DEMO_ENABLED` | false | 否 | 是否生成演示项目 |
| `TOMCAT_BASEDIR` | ./data/tomcat | 否 | Tomcat 临时目录 |

生成随机密钥：

```powershell
# PowerShell
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }))
```

```bash
# Linux
openssl rand -base64 48
```

### 6.2 前端配置

前端没有运行时配置，API 使用相对路径 `/api`，由 Vite 代理或 Nginx 转发。通常不需要改 `.env`。

## 7. 数据备份与恢复

### 7.1 数据库备份

```bash
mysqldump -h127.0.0.1 -P3306 -uresearch -p \
  --single-transaction --routines --triggers \
  research_material > /backup/research_material_$(date +%F).sql
```

Windows：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe" `
  --host=127.0.0.1 --port=3306 --user=research --password `
  --single-transaction --routines --triggers research_material > backup.sql
```

### 7.2 附件备份

```bash
tar -czf /backup/uploads_$(date +%F).tar.gz /opt/research-material/data/uploads
```

Windows：

```powershell
Compress-Archive -Path "backend\data\uploads\*" -DestinationPath "backup\uploads.zip"
```

### 7.3 恢复

1. 停止后端。
2. 恢复数据库。
3. 解压附件到 `STORAGE_ROOT`。
4. 启动后端。
5. 抽查附件下载和项目详情。

## 8. 升级流程

1. 备份数据库和附件。
2. 在测试环境执行增量 SQL。
3. 构建新后端 Jar 和前端 dist。
4. 停止后端 → 替换文件 → 启动后端。
5. Nginx 重新加载前端静态文件。
6. 验证健康检查、登录、项目列表、附件上传/下载、大屏。
7. 观察日志 30 分钟。

> 不要在生产直接执行 `db/schema.sql`，它会 `DROP TABLE`。生产升级请另写 `db/migration/Vx__xxx.sql`。

## 9. 常见问题

### 9.1 后端启动失败：`java.io.tmpdir is set to ... AccessDeniedException`

原因：Windows 临时目录权限受限。

解决：启动时指定 `-Djava.io.tmpdir` 和 `--server.tomcat.basedir` 到项目内可写目录。脚本已处理。

```powershell
java -Djava.io.tmpdir="F:\...\backend\tmp" -jar ... `
  --server.tomcat.basedir="F:\...\backend\data\tomcat"
```

### 9.2 `Port 8080 was already in use`

```powershell
Get-NetTCPConnection -LocalPort 8080
Stop-Process -Id <PID>
```

或改用 `--server.port=8081`。

### 9.3 登录提示“账号或密码错误”

- 确认执行了 `db/data.sql`。
- 确认密码大小写：`Admin@123`、`Manager@123`、`Viewer@123`。
- 数据库 `password_hash` 长度约 83，格式为 `pbkdf2$120000$...`。
- 若手工改过 hash，请用系统“重置密码”功能重新生成。

### 9.4 页面中文乱码

- 数据库、连接串、建表脚本均为 `utf8mb4`。
- 初始化时加 `--default-character-set=utf8mb4`。
- 确保 `db/schema.sql`、`db/data.sql` 为 UTF-8 无 BOM。

### 9.5 上传文件 413

- Nginx：`client_max_body_size 60m;`
- Spring：`spring.servlet.multipart.max-file-size=50MB`
- 业务限制：`app.storage.max-file-size-mb=50`

### 9.6 大屏 403

- 检查 URL 的 `?key=` 是否与 `DISPLAY_ACCESS_KEY` 一致。
- 修改环境变量后需重启后端。
- 点击大屏右上角钥匙图标可重新输入访问码。

### 9.7 前端接口 404

- 开发环境检查 Vite 代理是否指向 `http://127.0.0.1:8080`。
- 生产检查 Nginx `/api/` 是否 `proxy_pass http://backend:8080;`（不要多写 `/api`）。
- 检查后端是否启动。

### 9.8 Maven 构建失败（Jar 被占用）

Windows 下后端正在运行时，`mvn package` 无法覆盖 Jar。

```powershell
Get-Process java | Where-Object { $_.Path -like "*jdk-17*" } | Stop-Process
```

或先 `Ctrl+C` 停止后端。

### 9.9 附件下载 404

- 附件记录存在但磁盘文件丢失。检查 `STORAGE_ROOT` 是否变化。
- 恢复备份中的 `uploads` 目录。
- 数据库迁移时需同步附件。

### 9.10 时间显示偏差

- 服务器时区设置为 Asia/Shanghai。
- 数据库连接串包含 `serverTimezone=Asia/Shanghai`。
- 前端展示按浏览器本地时间格式化。
