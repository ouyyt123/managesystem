# 科研项目材料管理系统 · 交互原型

> 依据 `docs/01-需求规格说明书.md` 构建的可运行高保真原型：**无需安装数据库和前端工具链**，一条命令启动，重点验证「ERP 截图 OCR 建档」「流程模板拖拽编排」「材料拖拽归集」「项目—节点—材料—报表—经费」主流程。

- 运行环境：Node.js 20+；OCR 使用本机 Python + RapidOCR（已安装时自动启用，缺失时回退 Windows 内置 OCR）
- 默认地址：<http://127.0.0.1:8088>
- 演示大屏：<http://127.0.0.1:8088/display?key=research2026>
- 数据形态：`data/db.json` + `uploads/`（启动时自动生成演示数据）

## 1. 快速启动

### 方式一：双击脚本（推荐）

| 系统 | 文件 | 说明 |
| --- | --- | --- |
| Windows 命令提示符 | `start.cmd` | 自动寻找 Node；**如果服务已在运行，只打开浏览器，不会重复启动** |
| 停止服务 | `stop.cmd` | 只结束占用 8088 端口的本原型 Node 进程，不影响其他程序 |
| Windows PowerShell | `start.ps1` | 同上，执行策略受限时用 `powershell -ExecutionPolicy Bypass -File start.ps1` |

> 启动脚本已按 Windows cmd 的要求使用 ASCII + CRLF 保存，并通过 Node 输出中文提示，避免中文批处理在 GBK 控制台下被拆坏。若你之前双击时看到 `'ed' is not recognized` 之类的报错，属于旧脚本编码问题，现已修复。

启动器行为：

1. 检测 `http://127.0.0.1:8088/api/health` 已就绪 → 直接打开浏览器并退出；
2. 端口被其他程序占用 → 明确提示并停止，不会启动出错的第二个进程；
3. 端口空闲 → 启动服务，就绪后自动打开浏览器，窗口内按 `Ctrl+C` 停止。

### 方式二：命令行

```bash
cd prototype
node server/index.mjs
```

启动后访问 <http://127.0.0.1:8088>。端口被占用时可指定：

```bash
# Windows PowerShell
$env:PORT=8090; node server/index.mjs

# 门口大屏需要局域网其他设备访问时（默认仅本机）
$env:HOST='0.0.0.0'; node server/index.mjs
```

### 启动问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 双击后窗口一闪而过、浏览器打开 | 服务原本就在运行，启动器直接复用了它；关闭页面后可用 `stop.cmd` 停服务 |
| 提示 `端口 8088 已被其他程序占用` | 先运行 `stop.cmd`；若是别的程序占用，设置 `PORT` 换端口 |
| 提示 `Node.js 20+ was not found` | 安装 Node.js 后重开窗口，或把 `node.exe` 加入 PATH |
| PowerShell 提示禁止运行脚本 | 用 `start.cmd`，或执行 `powershell -ExecutionPolicy Bypass -File start.ps1` |
| 浏览器没有自动弹出 | 手动访问 <http://127.0.0.1:8088>，或查看窗口内是否打印了访问地址 |
| 端口占用但不知道是谁 | 运行 `stop.cmd` 只会结束本原型的 `server/index.mjs` 进程，不会误杀其他程序 |

> 首次启动会自动创建 `data/db.json`，并按“今天”为基准生成 5 个演示项目、20 项模板材料、季度报表、经费台账、附件与操作日志。修改代码后重启即可；前端静态文件无需构建。

### OCR 环境

OCR 优先使用本地 **RapidOCR + Python**（已在本机 DSH 自带 Python 中安装，模型离线，不上传云端）：

```bat
:: 需要重装时双击运行（自动寻找 Python 并安装 rapidocr_onnxruntime）
tools\setup-ocr.cmd

:: 或手动
python -m pip install rapidocr_onnxruntime
```

- RapidOCR 可用时识别效果最好（本例 ERP 截图可回填 21 个字段，约 2 秒）。
- 未安装 RapidOCR / Python 时，服务自动回退到 Windows 内置中文 OCR；准确率较低，但功能仍可用。
- 计算与上传均在本地完成，截图只在识别期间写入临时目录，识别后立即删除。

## 2. 拖拽交互说明（原型重点）

### 2.1 流程模板设计器 `/templates`

| 交互 | 操作 | 效果 |
| --- | --- | --- |
| 调整节点周期 | 按住时间轴上的节点块左右拖动 | 同时平移开始/结束比例（步进 1%） |
| 调整起止比例 | 拖动节点块左右边缘的把手 | 单独调整开始或结束比例 |
| 材料跨节点归类 | 拖动「材料编排」看板中的材料卡片到其他节点列 | 材料归属节点立即改变，编码/顺序自动维护 |
| 材料排序 | 在节点列内拖动卡片到目标卡片上方 | 卡片插入到目标位置 |
| 节点排序 | 拖动列头到另一列 | 节点顺序（seq）重排，新项目按新顺序生成 |
| 实时预览 | 顶部的「预览项目」选择器 | 按所选项目起止日期实时计算节点计划日期与材料截止日期 |
| 属性修改 | 右侧属性检查器 | 名称、编码、比例、偏移、锚点、必备/选交、允许补传等 |

保存规则遵循需求文档 FR-03：**模板变更只影响新项目，已生成项目保持快照，不追溯修改**。页面顶部会显示「有未保存的修改 / 已保存」状态。

### 2.2 项目材料归集 `/projects/:id`

- 把文件**直接拖到材料表格的某一行**，即上传到该材料（行高亮提示），适合逾期补传。
- 打开材料详情抽屉后，可继续拖拽或点击上传，支持多附件、补传说明、附件预览/下载/删除。
- 删除最后一个附件后，材料自动恢复为「待提交」；上传时间晚于截止日期自动标记「逾期提交」。
- 科研管理员可对材料执行「标记无需提交（必填原因）」和「重置为待提交」。

### 2.3 ERP 截图 OCR 建档 `新建项目`

新建项目弹窗顶部新增「ERP 截图识别」区，直接上传 ERP「项目基本信息」页截图即可：

- 自动识别项目名称、简称、项目代号、承担部门、负责人、计划起止时间、合同运行额、成本控制额、税款类别、代号类型、计划利润、预立项、重大立项、结算状态、立项时间/序号、项目总工、安全员、是否转化项目、工期、立项经费说明、备注等字段，并回填到表单。
- 识别结果用淡紫色边框标记；右上角「允许修改识别结果」开关关闭后，所有识别字段锁定，避免误改；重新打开即可修改。
- 成本控制额（元）自动按 `÷10000` 换算批复经费（万元）。
- 同时显示 OCR 原始文本和“待确认”提示；识别失败或字段不匹配时可继续手工填写。
- 本地识别，不上传外部云服务。RapidOCR 不可用时自动回退 Windows 内置中文 OCR（准确率略低）。

### 2.4 项目字段配置 `系统管理 → 项目字段`

新建项目表单已按 ERP「基本信息」页重构为 **ERP 基本信息 + 系统信息** 两组字段，可由管理员/科研管理员继续调整：

- **新增**字段：单行文本、多行文本、数字、日期、下拉选择、是/否勾选；可设必填、整行、占位提示、说明、所属分组与 OCR 关键词。
- **修改**：改名称、类型、必填、分组、顺序、提示；拖拽行调整表单顺序。
- **删除**：自定义字段可删除；内置字段不可删除，可停用。
- **字段内容（下拉选项）**：下拉字段行内点「选项」即可对选项内容增删改、上下移动，保存配置后生效。
- **OCR 关键词**：每个字段可配置多个关键词（如“项目名称, 顶目名称”），OCR 按关键词定位并回填。
- 项目名称、部门、经理、起止日期、经费、状态等锁定字段不可停用，保证日期计算、权限与统计规则不被破坏。

### 2.5 菜单启停 `系统管理 → 菜单管理`

- 左侧菜单支持逐项启用/停用，停用后导航隐藏，直接访问地址会提示「该菜单已停用」。
- 运行总览、项目台账、系统管理为锁定菜单，避免管理员把自己锁在系统外。
- 保存后页面自动刷新，菜单状态与权限校验同时生效。

### 2.6 其他可修改内容

项目台账新建/编辑（起止日期改动会重算未提交材料截止日期）、季度报表填报/提交/撤回、经费支出增删改、用户/部门维护、模板增删启停，均写入 `data/db.json`。

## 4. 技术实现（原型取舍）

```text
prototype/
├─ server/
│  ├─ index.mjs       零依赖 HTTP 服务：静态资源 + REST API + 会话校验
│  ├─ store.mjs       JSON 持久化（原子写入）、上传目录、演示 PDF 生成
│  ├─ auth.mjs        PBKDF2 密码、HMAC-SHA256 Token
│  ├─ dates.mjs       周期/季度/截止日期规则、状态字典
│  ├─ services.mjs    项目快照生成、统计、提醒、分类台账、大屏聚合
│  ├─ project-fields.mjs  ERP/系统字段配置、OCR 关键词、自定义值归一化
│  ├─ ocr.mjs         OCR 引擎调度、ERP 字段解析（RapidOCR / Windows 兜底）
│  ├─ menus.mjs       菜单启停配置
│  └─ seed.mjs        可重复生成的演示数据
├─ public/
│  ├─ index.html      SPA 入口
│  ├─ styles/app.css  设计系统（深色侧栏 → 浅色工作台；大屏暗色主题）
│  └─ js/
│     ├─ app.js       路由、布局、会话、菜单启停、账号菜单
│     ├─ core/        API、图标、格式化、弹窗抽屉、图表、数据缓存
│     └─ views/       登录/看板/项目/详情/模板/季度/提醒/分类/系统/大屏
├─ tools/
│  ├─ ocr.py          RapidOCR 适配器（本地 Python）
│  ├─ ocr.ps1         Windows OCR 兜底
│  ├─ verify.mjs      CDP 自动化验证（OCR、权限、拖拽、菜单、响应式、大屏）
│  └─ screenshot.mjs  逐页截图与前端异常收集
├─ data/              运行时生成（db.json、token.secret）
├─ uploads/           运行时附件，按年/月分目录
└─ screenshots/       验证截图
```

设计取舍：

1. **不引入 Spring Boot + MySQL**：原型目标是验证交互与业务规则，Node 单进程 + JSON 文件可让评审同事双击即看；正式系统仍按 `docs/02` 的 Java/MySQL 架构落地。
2. **不引入 Vue/Vite/Element Plus**：使用原生 ES Module 与手写组件，避免离线环境 npm 安装失败；交互与视觉按现代后台系统标准实现，后续可平移至 Vue 3。
3. **接口契约保持 `/api/**` 与统一响应 `{code,message,data}`**：替换 `public/js/core/api.js` 的 `api()` 实现即可对接正式后端，页面不需要重写。
4. **OCR 放在服务端适配层**：`/api/ocr` 内部先调 RapidOCR（本地 Python），失败回退 Windows OCR；正式系统可把 `server/ocr.mjs` 的识别实现替换为百度/腾讯/自建 OCR 服务，前端与字段映射不需要改。
5. **附件走 JSON Base64 上传**（单文件 ≤ 20MB）：原型不引入 multipart 解析；正式系统按文档使用流式上传、SHA-256 与对象存储。
6. **安全为演示级别**：Token 存 localStorage、访问码固定为 `research2026`；正式系统需 HTTPS、HttpOnly、防重放与审计加固。

## 7. 已知边界

- 单机单用户演示：多个浏览器标签共享同一份 JSON 数据，未做并发写锁。
- OCR 准确率依赖截图清晰度与版式；本原型按标准 ERP「基本信息」表格做关键词定位，换版式时可通过字段配置里的「OCR 关键词」调整。
- 不含真实审批流、电子签章、消息推送、集团统一认证；需求文档已明确这些不在本期范围。
- 大屏访问码为固定演示值，正式环境应通过环境变量 `DISPLAY_KEY` 覆盖并定期更换。
- 附件预览依赖浏览器能力（PDF/图片/文本可直接预览，Office 文件以下载为主）。
- 本原型不替代 `docs/02` 的技术设计，生产实现仍以 Spring Boot + MySQL + Vue 3 为准。

## 8. 从原型到正式系统

1. 以 `server/index.mjs` 的路由清单为接口基线，对齐 `docs/06-API接口清单.md`。
2. 将 `public/js` 的视图逐页迁移到 Vue 3 单文件组件，`core/api.js` 保持不变即可。
3. 日期/状态规则已在 `server/dates.mjs` 与 `server/services.mjs` 中独立，可直接转写为 Java 工具类与服务层。
4. 模板设计器的拖拽模型（比例 + 偏移、快照生成）可直接复用为正式系统“流程模板”页面。
